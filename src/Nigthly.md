# 🚂 Краткое объяснение: Как создаётся Rust и Nightly Rust

## 🔹 Стабильность без стагнации  
Rust даёт **стабильность**, но не стоит на месте.  
Обновления всегда **безболезненны** и приносят новые возможности, улучшения и скорость.

---

## 🚆 Модель «поезда» (Train Model)  
Разработка идёт в **ветке master**, а релизы проходят через **три канала**:

| Канал | Описание |
|-------|----------|
| **Nightly** | Ежедневные сборки с новейшими (нестабильными) фичами |
| **Beta** | Кандидат на релиз, тестируется 6 недель |
| **Stable** | Финальный стабильный релиз каждые **6 недель** |

> 💡 Если фича не успела — не страшно, следующий «поезд» скоро!

---

## ⚙️ Нестабильные функции (Feature Flags)  
- В **Nightly** новые фичи доступны через **флаги** (`#![feature(...)]`).
- В **Beta** и **Stable** флаги **отключены** — код надёжен.

---

## 🛠️ Rustup — переключение каналов  
```bash
# Установка nightly
rustup toolchain install nightly

# Переключение для конкретного проекта
cd ~/projects/needs-nightly
rustup override set nightly
```

---

## 📝 Процесс RFC (Request For Comments)  
1. Любой пишет **предложение** по улучшению.  
2. Команда Rust обсуждает, принимает или отклоняет.  
3. Реализация попадает в **master** с флагом.  
4. После тестирования в Nightly — фича становится **стабильной**.  

---

## ✅ Итог  
- **Стабильность** — основа.  
- **Nightly** — для экспериментаторов.  
- **Процесс** — открытый, прозрачный и регулярный.  

> «Стабильность без застоя» — главный принцип Rust.
